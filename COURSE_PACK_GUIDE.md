# Course Pack для QuizMind Yandex

Course Pack — это подготовленный JSON-файл с небольшими фрагментами лекций. Когда режим включён, QuizMind Yandex локально находит подходящие фрагменты и добавляет только их в запросы Chat и Yandex Forms. Это помогает отвечать в формулировках и логике конкретного курса.

## Почему JSON, а не исходные лекции

Исходные PDF, DOCX и презентации приходится заново распознавать и разбирать при каждом запросе. Подготовленный Course Pack:

- загружается и проверяется один раз;
- быстро ищется локально, без отдельного запроса к модели;
- передаёт модели только релевантные фрагменты;
- не требует хранить в расширении PDF, изображения или base64.

QuizMind Yandex не выполняет OCR и не создаёт chunks автоматически. Текст и описания визуальных слайдов нужно подготовить заранее.

Текущие технические ограничения: JSON до 8 МБ, до 500 лекций и до 2000 chunks. В один запрос попадает максимум 8 наиболее релевантных chunks общим объёмом до 8000 символов.

## Схема `quizmind.coursepack.v1`

```json
{
  "schema": "quizmind.coursepack.v1",
  "courseId": "demo-marketing-2026",
  "title": "Introduction to Product Marketing",
  "language": "en",
  "createdAt": "2026-06-30",
  "description": "Optional description",
  "lectures": [
    {
      "lectureId": "week-1-basics",
      "title": "Marketing Basics",
      "source": "Lecture 1.pdf",
      "pages": 24
    }
  ],
  "chunks": [
    {
      "id": "week-1-basics-p5-positioning",
      "lectureId": "week-1-basics",
      "lectureTitle": "Marketing Basics",
      "source": "Lecture 1.pdf",
      "page": 5,
      "heading": "Positioning",
      "text": "Positioning explains how a product should be perceived by a chosen audience relative to alternatives.",
      "keywords": ["positioning", "audience", "alternatives"],
      "visualDescription": "A simple map compares products by price and specialization."
    }
  ]
}
```

Обязательные поля верхнего уровня:

- `schema` — строго `quizmind.coursepack.v1`;
- `courseId` — непустой стабильный идентификатор курса;
- `title` — название курса;
- `lectures` — минимум одна лекция;
- `chunks` — минимум один фрагмент.

Для каждого chunk обязательны:

- `id` — уникальный идентификатор;
- `lectureId` — ссылка на элемент из `lectures`;
- `lectureTitle` или возможность получить название через `lectureId`;
- `page` — номер страницы или слайда, начиная с 1;
- `text` или `visualDescription`.

Расширение сохраняет только разрешённые поля. Неизвестные поля, бинарные данные и другие вложения отбрасываются.

## Полный процесс генерации с помощью AI

Ниже приведён рекомендуемый workflow для AI-агента или мультимодальной модели, которая готовит Course Pack. Генератор должен работать со **всеми** переданными источниками, а не только с файлами, из которых легко извлекается текст.

1. **Составить список источников.** Прочитать имена файлов и доступные метаданные, определить отдельные лекции, презентации, задания и проектные материалы. Для каждого источника заранее назначить стабильный `lectureId`.
2. **Прочитать все источники целиком.** Зафиксировать реальное количество страниц или слайдов. Не ограничиваться оглавлением, первыми страницами или поисковой выдачей по документу.
3. **Извлечь текстовый слой.** Получить parsed text для каждой страницы PDF или соответствующего блока DOCX/PPTX. Сохранить связь текста с номером страницы и источником.
4. **Отрендерить и просмотреть страницы.** Создать изображения страниц или слайдов и визуально проверить их, особенно если parsed text короткий, повреждён или отсутствует.
5. **Выполнить OCR при необходимости.** Распознать видимый текст на сканах, схемах, скриншотах интерфейсов и image-only слайдах. Очистить переносы, повторяющиеся колонтитулы и очевидные OCR-ошибки.
6. **Интерпретировать визуальную часть.** Для диаграмм, таблиц, карт, схем, композиций и других значимых изображений написать `visualDescription`: что показано, какие элементы связаны и какой учебный вывод следует из изображения.
7. **Объединить три источника сигнала.** Итог страницы строится из PDF text layer, OCR и визуальной интерпретации. Ни один из этих источников не считается автоматически полным или безошибочным.
8. **Создать page-level chunks.** Для каждой содержательной страницы подготовить один или несколько chunks с корректными `source`, `page`, `lectureId`, `lectureTitle`, `heading`, `text`, `keywords` и при необходимости `visualDescription`.
9. **Создать curated summary/index chunks.** После обработки страниц добавить небольшие проверенные сводные chunks для обзора курса, отдельных лекций, крупных тем, проектного контекста и часто проверяемых понятий.
10. **Добавить keywords на английском и русском.** Включить точные термины, синонимы, сокращения и формулировки, похожие на вопросы теста.
11. **Проверить и валидировать JSON.** Проверить schema, типы полей, уникальность IDs, ссылки `lectureId`, номера страниц, лимиты и отсутствие запрещённых данных.
12. **Сформировать отчёт.** Рядом с JSON создать `course_pack_report.md` с покрытием источников, статистикой chunks, OCR/visual notes, результатами валидации и известными ограничениями.

### Критическое правило: не пропускать «пустые» страницы

Страница с пустым parsed text **не является пустой автоматически**. Генератор обязан открыть её отрендеренное изображение и проверить визуальное содержимое.

- Если на странице есть видимый текст — выполнить OCR и добавить очищенный результат в `text`.
- Если основная информация передана изображением, схемой или диаграммой — заполнить `visualDescription`.
- Если есть и текст, и значимая визуальная структура — сохранить очищенный текст и описание визуальной части.
- Пропустить страницу можно только после визуальной проверки, если она действительно не содержит учебной информации, например это полностью пустой разделитель.

Не используйте правило «parsed text пустой → страницу пропустить». Для презентаций оно почти всегда приводит к потере image-only слайдов.

### PDF text layer + OCR + visual interpretation

Лучший результат получается объединением трёх представлений страницы:

- **Text layer** даёт точный машинный текст, если PDF создан корректно.
- **OCR** восстанавливает текст из сканов и изображений, но может ошибаться в формулах, таблицах, именах и мелких подписях.
- **Visual interpretation** объясняет структуру, которую нельзя передать простым OCR: оси графика, направления стрелок, группировку элементов, сравнения и причинно-следственные связи.

AI-генератор должен сопоставлять эти представления, удалять дубли и не выдавать предположение за факт. Если часть изображения не читается уверенно, это нужно отметить в отчёте, а не дополнять вымышленными деталями.

## Как делить материал

Рекомендуемый размер одного chunk — **500–1200 символов**. Один chunk должен описывать одну идею, один слайд или один логический блок. Не объединяйте целую лекцию в один огромный фрагмент: поиск станет менее точным, а запросы — длиннее.

Хорошие идентификаторы стабильны и читаемы:

- `lectureId`: `week-03-brand-identity`;
- `id` для chunk: `week-03-brand-identity-p12-logo-elements`.

Не меняйте идентификаторы при небольшом редактировании текста.

### Page-level и curated summary chunks

Основу Course Pack составляют page-level chunks: они сохраняют точную связь с конкретной страницей и источником. Дополнительно рекомендуется создать curated summary/index chunks для:

- общего обзора курса;
- каждой отдельной лекции;
- крупных сквозных тем;
- assignment/project context;
- понятий, которые часто встречаются в тестах и вариантах ответа.

Summary chunk должен быть составлен **только из уже проверенных материалов**. Он может объединять связанные идеи с нескольких страниц, но не должен добавлять факты, которых нет в источниках. Для summary chunks используйте реальный `lectureId`, подходящий `page` исходного материала и явно описывайте назначение в `heading`, например `Lecture overview` или `Frequently tested concepts`.

## Задания и студенческие работы как источники

Assignments, briefs, project examples и студенческие работы можно включать в Course Pack, если они нужны для понимания требований курса или проектного контекста.

- Используйте отдельные `lectureId` с префиксом `assignment-`, например `assignment-brand-audit`.
- В `title`, `heading` или `description` явно отмечайте, что это **project context / assignment context**, а не лекционная теория.
- Не переносите утверждения из одной студенческой работы в общую теорию курса.
- Для quiz/Yandex Forms answers лекционная теория имеет приоритет над assignments и student works.
- Если assignment противоречит лекции, сохраняйте оба источника корректно, но не переписывайте лекционное правило под пример проекта.
- Не включайте персональные данные студентов, приватные комментарии преподавателя и материалы, на хранение которых нет разрешения.

## Keywords

Для каждого chunk рекомендуется **4–15 точных keywords**. Добавляйте термины, которые реально помогают найти chunk по вопросу или варианту ответа:

- основной термин на английском и русском, если оба варианта могут встретиться в курсе;
- точные синонимы и распространённые варианты написания;
- сокращения и их расшифровки;
- quiz-like terms: слова из определений, сравнений, классификаций и типичных формулировок вопросов;
- названия моделей, методов, авторов и категорий;
- короткие характерные примеры со слайдов, если по ним может быть сформулирован вопрос.

Не добавляйте случайные ассоциации и не копируйте длинные предложения. Keywords должны отражать только фактическое содержание chunk. Лучше 6 точных терминов, чем 30 общих слов.

## Визуальные слайды и OCR

Если смысл находится в диаграмме, схеме или изображении, заполните `visualDescription`. Опишите связи, подписи, направления стрелок и вывод, который студент должен сделать из изображения.

Для сканов и image-only слайдов сначала выполните OCR. Проверьте распознанный текст вручную. Если OCR не справился, добавьте краткий корректный текст или `visualDescription` самостоятельно.

AI-генератор обязан отдельно отметить в отчёте страницы, где использовался OCR, где потребовалась визуальная интерпретация и где содержимое осталось частично неразборчивым.

## Безопасность и авторские материалы

Не включайте в Course Pack:

- исходные PDF/DOCX/PPTX;
- base64-изображения;
- сканы страниц;
- API-ключи, cookies или локальные пути;
- большие дословные копии материалов, если у вас нет права их хранить и использовать.

Храните только необходимые учебные фрагменты и метаданные источника.

## Обязательный отчёт генерации

Вместе с Course Pack создайте файл `course_pack_report.md`. Он нужен для быстрой проверки полноты и качества генерации и не загружается в QuizMind Yandex.

Отчёт должен содержать:

- имя сгенерированного JSON-файла;
- schema, например `quizmind.coursepack.v1`;
- `courseId` и `title`;
- полный список обработанных sources;
- количество chunks для каждого источника;
- итоговый размер JSON-файла;
- OCR/visual notes: какие страницы распознавались или описывались визуально;
- результаты schema/JSON validation;
- ограничения и сомнительные места: нечитабельные страницы, отсутствующие файлы, неуверенный OCR, неоднозначные номера страниц.

Практичный минимальный шаблон:

```markdown
# Course Pack generation report

- Generated file: course-pack.json
- Schema: quizmind.coursepack.v1
- Course: demo-course-2026 — Demo Course
- File size: 420 KB
- Validation: passed

## Sources and coverage

| Source | Pages | Chunks | OCR / visual notes |
| --- | ---: | ---: | --- |
| Demo Lecture 1.pdf | 24 | 31 | OCR on pages 7–8; diagram described on page 12 |

## Limitations

- One small chart label on page 12 could not be read confidently.
```

Не помещайте в отчёт полный текст лекций, base64, приватные пути или чувствительные данные.

## Финальный checklist для AI-генератора

Перед передачей результата пользователю AI-генератор обязан убедиться, что:

- [ ] Все переданные sources представлены в `lectures` и покрыты chunks либо объяснены в отчёте.
- [ ] Количество страниц для каждого источника проверено и указано правильно.
- [ ] Все `lectureId` и chunk `id` уникальны и стабильны.
- [ ] Каждый chunk ссылается на существующий `lectureId`.
- [ ] Каждый chunk содержит непустой `text` или `visualDescription`.
- [ ] Страницы с пустым parsed text просмотрены как изображения; визуальные слайды не пропущены.
- [ ] PDF text layer, OCR и visual interpretation сопоставлены, а дубли удалены.
- [ ] OCR очищен от очевидных ошибок, повторяющихся колонтитулов и лишних переносов.
- [ ] Summary chunks основаны только на источниках и не содержат придуманных фактов.
- [ ] Assignment/student-work chunks отмечены как project context; теория лекций сохраняет приоритет.
- [ ] Keywords содержат 4–15 точных EN/RU терминов, синонимов и quiz-like формулировок.
- [ ] В JSON нет base64, raw PDF/DOCX/PPTX, API-ключей, cookies и приватных локальных путей.
- [ ] JSON синтаксически корректен и проходит schema validation.
- [ ] Соблюдены лимиты размера файла, количества лекций, chunks и длины полей.
- [ ] Создан `course_pack_report.md` со статистикой, validation results и limitations.

Если какой-либо пункт нельзя подтвердить, генератор должен явно указать это в `course_pack_report.md`, а не скрывать проблему и не дополнять данные предположениями.

## Использование

1. Откройте настройки QuizMind Yandex.
2. Выберите **Материалы курса / Course Pack**.
3. Нажмите **Загрузить Course Pack (.json)**.
4. Проверьте название курса, число лекций и chunks.
5. Включите режим материалов курса.
6. Отдельно включите или выключите использование в Chat и Yandex Forms.
7. Чтобы удалить данные, нажмите **Удалить материалы курса**.

Отключение режима немедленно возвращает обычное поведение QuizMind Yandex. Очистка истории Chat не удаляет Course Pack.

Небольшой искусственный пример находится в [`examples/course-pack.example.json`](examples/course-pack.example.json).
